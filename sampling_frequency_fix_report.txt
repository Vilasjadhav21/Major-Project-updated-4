3. SCIENTIFIC JUSTIFICATION & DATASET ORIGIN
--------------------------------------------------------------------------------
PhysioNet TPEHGDB v1.0.1 documentation confirms:
1. Physical Acquisition:
   All uterine EMG/EHG recordings were acquired using an A/D hardware clock rate of 20 Hz.
2. File Generation Artifact:
   For 126 recordings of 36,000 samples lasting 1799.99 seconds, the clock frequency ratio
   (36,000 / 1799.99 = 20.0001111... Hz) was stored in ASCII header format as '20.000110'.
   For the remaining 174 recordings (e.g., 35,180 samples / 1759.0 seconds), the header
   specifies '20.000000'.
3. Spectral and Temporal Impact:
   - For the 1-minute window (1200 samples), the discrete Fourier transform bin spacing is
     Delta_f = fs / N = 20.0 / 1200 = 0.016667 Hz.
   - The frequency bin shift induced by 0.00011 Hz is:
     0.00011 / 1200 = 9.17 x 10^-8 Hz, which is more than 180,000 times smaller than the
     spectral bin width.
   - The temporal window difference over 60 seconds is 0.00033 seconds (0.33 ms).
   - Conclusion: Treating 20.00011 Hz as nominal 20.0 Hz with an explicit tolerance is
     scientifically sound, preserves biological fidelity, and avoids artificial sample loss.

4. REPLACEMENT WITH DOCUMENTED TOLERANCE
--------------------------------------------------------------------------------
The inappropriate exact equality comparisons were replaced with an explicit tolerance
(fs_tolerance = 0.01 Hz):

1. src/config.py (DatasetConfig):
   Added documented configuration parameter:
       sampling_frequency: float = 20.0  # Hz
       sampling_frequency_tolerance: float = 0.01  # Hz tolerance for hardware/header representations

2. src/process_all_records.py:
   Replaced:
       actual_fs = float(wfdb_rec.fs)
       fs_tolerance = 0.01  # Documented tolerance in Hz for TPEHGDB v1.0.1
       if abs(actual_fs - expected_fs) > fs_tolerance:
           raise ValueError(f"Sampling frequency mismatch: Expected {expected_fs} Hz (+/- {fs_tolerance} Hz), got {actual_fs} Hz.")

3. src/feature_extraction.py (extract_features):
   Replaced:
       fs_tolerance = 0.01  # Documented tolerance in Hz for TPEHGDB v1.0.1
       if abs(float(sampling_frequency) - 20.0) > fs_tolerance:
           raise ValueError(f"Sampling frequency must be 20 Hz (+/- {fs_tolerance} Hz tolerance for TPEHGDB headers), got {sampling_frequency} Hz.")

4. src/extract_features_single_record.py:
   Replaced exact check with:
       fs_ok = abs(sampling_frequency - 20.0) <= 0.01

Protection:
Any true anomalous sampling frequency (e.g., 10 Hz, 50 Hz, 100 Hz, 1000 Hz) outside
the [19.99 Hz, 20.01 Hz] interval will continue to be strictly rejected.
